AGENTS.md — что это и зачем он нужен
=====================================

Файл: AGENTS.md (лежит в корне проекта, рядом с этим файлом)
Кому адресован: агенту OpenCode (ИИ), а не программе и не серверу IntraSCADA.


1. Что это такое
----------------
AGENTS.md — стандартный файл проектных инструкций OpenCode (аналог .editorconfig
или coding guidelines, но для ИИ-агента). Это обычный текст в Markdown.
Никакой код его не исполняет: его читает агент при старте работы с проектом
и держит в контексте как обязательные правила.

В OpenCode V2 подхватывается только имя AGENTS.md (CLAUDE.md как запасной
вариант больше не используется). Файл ищется от текущей рабочей папки вверх
до корня проекта, поэтому один AGENTS.md в корне покрывает все подпапки.


2. Зачем он здесь
-----------------
Чтобы агенту не приходилось объяснять одно и то же в каждой новой сессии, и
чтобы правила не потерялись при смене сессии/модели. Сейчас в нём два правила:

  Раздел 1. Работать только через папку проекта и её .git.
    - Все правки — внутри C:\ProgramData\IntraSCADA\intrascada\projects\LIMS_v2_0.
    - Не использовать worktree, клоны и копии проекта для правок.
    - Git-команды выполнять только в папке проекта.
    - Коммиты и прочие изменения истории — только по прямой просьбе владельца.
    - Отчёт о работе строить по реальному "git status" этой папки.

  Раздел 2. База данных.
    - Живая база: db\sqliteDb\hist.db; править только через SQL, не текстом.
    - Перед изменением живой базы — резервная копия.
    - Порядок: миграция в db\migrations\ -> node db\dump-schema.cjs ->
      node db\verify-migrations.cjs -> node db\dump-schema.cjs --check.
    - Текстовые артефакты схемы коммитятся вместе с базой.


3. Почему именно так
--------------------
- Раньше работа шла в отдельной git-worktree копии, и изменения не были видны
  в VS Code, открытом на папке проекта. Правило фиксирует: работаем в проекте.
- Бинарный hist.db нельзя править текстовыми инструментами (формат сломается),
  а в диффе от него видно только "Bin ... bytes". Отсюда требование вести
  структуру через миграции и db\schema.sql.
- Правила в файле, а не в переписке: они применяются к каждой новой сессии.


4. Как это работает на практике
-------------------------------
- Файл читается автоматически при старте сессии в этом проекте — ничего
  запускать не нужно.
- Изменили AGENTS.md во время работы — OpenCode подхватит правку до следующего
  запроса к модели.
- Файл стоит держать в git: тогда правило действует для всех, кто работает
  с этим репозиторием. Изменения видны в VS Code как обычный текстовый дифф.
- Дополнять можно любыми правилами: команды сборки, конвенции кода, запреты,
  порядок проверок. Чем конкретнее формулировка, тем предсказуемее поведение.


5. Чего в нём быть не должно
----------------------------
- Секретов, паролей, токенов (файл коммитится в репозиторий).
- Одноразовых заметок и задач «на сегодня» — для этого текущая переписка.
- Дублирования db\README.md: подробности про базу лежат там, в AGENTS.md —
  только сами правила и ссылка.


6. Связанные файлы
------------------
- db\README.md, db\migrations\README.md — как устроены схема и миграции БД.
- db\dump-schema.cjs, db\verify-migrations.cjs — скрипты проверки, упомянутые
  в правиле про базу данных.
