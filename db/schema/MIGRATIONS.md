# Миграции структуры БД

Лежат в этой же папке (`db/schema`), рядом с `schema.sql` и скриптами. Каждый
файл — одно изменение структуры. Смысл: любую копию базы можно собрать/догнать
текстовыми командами, а не ручными кликами в SQLiteStudio.

## Правила

1. **Имя файла:** `NNNN_короткое_описание.sql`, где `NNNN` — четыре цифры
   (`0001`, `0002`, … `0010`). Латиница, цифры, `_`. Пример:
   `0003_add_vk_zvk_status_fk.sql`.
   Именно по шаблону `NNNN_*.sql` скрипт проверки отличает миграции от
   `schema.sql`, документации и кода — иначе файл в цепочку не попадёт.
2. **Порядок применения = порядок имён** (лексикографическая сортировка).
   Пропускать номера нельзя — следующий файл продолжает предыдущий.
3. **Файл неизменяем**, начиная с момента, когда его применили к рабочей базе.
   Нашли ошибку — пишем следующий файл, который её исправляет.
4. `0001_init.sql` — замороженный базовый снимок схемы (без данных).
   Он не перегенерируется, даже если структура изменилась.
5. Данные в миграции попадают только осознанно (`INSERT` справочников).
   Массовая выгрузка данных — не сюда.

## Чек-лист перед коммитом

```powershell
node db/schema/dump-schema.cjs         # обновить снимок структуры
node db/schema/verify-migrations.cjs   # цепочка миграций = реальная структура?
git status                             # в коммите: hist.db + schema.sql + новый .sql
```

`verify-migrations.cjs` должен ответить `ok`. Если он пишет
`нет в миграциях` — структуру изменили в базе, но миграцию не написали.

## Шаблон файла

Простое добавление столбца (без внешнего ключа) — обычный `ALTER`:

```sql
-- 0003_add_vk_provider_note.sql
-- Что делает: добавляет vk_provider.note TEXT.
BEGIN;
ALTER TABLE vk_provider ADD COLUMN note TEXT;
COMMIT;
```

Добавление столбца-внешнего ключа так сделать **нельзя**: SQLite запрещает
`ADD COLUMN` с `REFERENCES` и значением по умолчанию, отличным от `NULL`
(`Cannot add a REFERENCES column with non-NULL default value`), а конвенция
проекта требует `DEFAULT (0)` (ссылка на строку `id=0` «не задано»).
Тогда таблица пересобирается — рабочий образец: `0002_add_vk_shipment_id_prod_item.sql`.

Каркас пересборки:

```sql
PRAGMA foreign_keys = OFF;
BEGIN;

-- 1) сохранить данные
CREATE TABLE <table>_old AS SELECT * FROM <table>;

-- 2) удалить старую (её триггеры удалятся вместе с ней)
DROP TABLE <table>;

-- 3) создать новую — DDL ровно в нужном виде
CREATE TABLE <table> ( ... );

-- 4) вернуть данные, перечислив столбцы явно
INSERT INTO <table> (col1, col2, ...)
SELECT col1, col2, ... FROM <table>_old;

DROP TABLE <table>_old;

-- 5) восстановить автоинкремент (DROP TABLE стирает строку из sqlite_sequence)
INSERT INTO sqlite_sequence (name, seq)
SELECT '<table>', COALESCE((SELECT MAX(id) FROM <table>), 0)
 WHERE NOT EXISTS (SELECT 1 FROM sqlite_sequence WHERE name = '<table>');

-- 6) пересоздать триггеры таблицы
CREATE TRIGGER ... ;

COMMIT;
PRAGMA foreign_keys = ON;
```

Почему через `CREATE TABLE ... AS SELECT`, а не через переименование:
`ALTER TABLE ... RENAME TO` заставляет SQLite переписать DDL в `sqlite_master`
с кавычками (`CREATE TABLE "vk_shipment" (...)`), и файл `schema.sql` начинает
отличаться от текста миграции. Способ выше такого не делает.

## Что учитывать

- **Не идемпотентно.** Реестра применённых миграций нет: повторный накат `0001`
  упадёт (`table already exists`), повторный накат `0002` обнулит `id_prod_item`.
  Накатывать по одному разу и по порядку; перед накатом делать копию файла базы.
- **`PRAGMA foreign_keys = OFF`** нужен, чтобы `DROP TABLE` не сработал по
  дочерним таблицам (`vk_zvk.id_shipment` ссылается на `vk_shipment`).
  Учтите: `PRAGMA` не действует внутри транзакции, поэтому он стоит **до** `BEGIN`.
- **`PRAGMA foreign_key_check` на этой базе не работает** — давняя ошибка схемы:
  `vk_zvk.status` объявлен как `REFERENCES zv_status (id_pk)`, а в `zv_status`
  колонки `id_pk` нет (есть `id`). Пока это не исправлено отдельной миграцией,
  проверяйте ссылки вручную.
- **Повреждённые таблицы** `records`, `timeline`, `customtable` не мешают
  миграциям структуры, но операции, читающие их данные, упадут.
