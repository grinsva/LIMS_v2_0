# IntraScada UI — скилл для OpenCode

Переносимый скилл для работы с интерфейсом IntraSCADA в любом проекте: файлы
`jbase`, контейнеры, раскладки, шаблоны, диалоги, устройства и тревоги,
локальные переменные, картинки, веб-клиент и безопасный порядок выдачи
изменений.

Версия 2: объединяет два независимо собранных набора — «формат проекта +
устройства + плитки + проверки» и «кнопки, локальные переменные, картинки,
рантайм клиента».

## Установка

Глобально (для всех проектов на машине):

```text
C:\Users\<user>\.config\opencode\skills\intrascada-ui\
```

В конкретный проект:

```text
<проект>\.opencode\skills\intrascada-ui\
```

Важно: каталог называется `skills` (множественное число), ID скилла — имя
папки, то есть `intrascada-ui`. После сохранения `SKILL.md` скилл подхватывается
без перезапуска. Проверка — упомянуть `@intrascada-ui` в запросе.

Не держите рядом вторую копию под другим ID (`intrascada`): в списке появятся
две конкурирующие записи с одинаковым описанием.

## Что нового в версии 2

- Кнопки и действия: обязательные поля, команды, `actions.left/right`,
  `setval_any` для локальных переменных, переходы `layout`/`dialog_any`.
- Локальные переменные `localNNN`: структура записи, `defval`, время жизни,
  привязка полей через `did`/`prop`/`func`.
- Подмена контейнера по локальной переменной — проверено по коду сборки:
  пересчёт `link.id` при `setval_any` с `local: true`.
- Картинки: `images\` + `images.db`, URL `/images/<файл>`, перекраска только
  SVG через `imgColor`, `.ico` с PNG-кадром.
- Веб-клиент: поиск по актуальной сборке `main.<hash>.chunk.js`, прямые ссылки
  в админку, проверка отдачи картинок по `Content-Type`.
- Официальная документация: карта разделов + скрипт `docs.js` для адресного
  чтения одной страницы по alias/id, с локальным кэшем.
- Проверки: чек-лист новой сущности (файл + запись журнала), таблица привязок,
  обязательные поля элементов.
- Правила выдачи: режим «отдельный файл в `bak/`» остаётся по умолчанию,
  прямая правка живого файла — только с явного разрешения.

## Требования

- Node.js 18+ (без npm-зависимостей).
- Чтение каталога проекта; запись — только туда, куда разрешил пользователь.
- Windows: пути с пробелами и кириллицей брать в кавычки.

## Быстрая проверка

```bash
node scripts/list-devices.js --project "<проект>" --folder dg172
node scripts/validate-container.js "<...>\vc001.json" --project "<проект>"
node scripts/container-preview.js "<...>\vc001.json" --project "<проект>" --out preview.html
node scripts/docs.js page button
node scripts/docs.js search deviceValue
```

Скриншот превью 1:1:

```powershell
& "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" `
  --headless=new --disable-gpu --hide-scrollbars `
  --user-data-dir="$env:TEMP\edge-shot-profile" `
  --window-size=1740,1000 --screenshot="$env:TEMP\preview.png" `
  "file:///C:/path/to/preview.html"
```

## Настройка под другой проект

Скрипты не содержат зашитых путей: проект передаётся `--project` или
переменной окружения `INTRASCADA_PROJECT`.

```powershell
$env:INTRASCADA_PROJECT = "D:\SCADA\projects\OTHER"
```

Если в другом проекте другие шаблоны плиток, диалоги или локальные переменные —
проверить по существующим элементам и поправить соответствующие разделы
`references/templates-devices.md` и `references/controls-locals.md`.

## Экспорт

Zip:

```powershell
Compress-Archive -Path "C:\Users\<user>\.config\opencode\skills\intrascada-ui" `
                 -DestinationPath "intrascada-ui-skill-v2.zip"
```

Git:

```bash
cd intrascada-ui
git init && git add . && git commit -m "intrascada-ui skill v2"
git tag v2
```

На другой машине распаковать в `~/.config/opencode/skills/`.

## Чего в скилле быть не должно

- Паролей, токенов, ключей.
- Абсолютных путей конкретной машины внутри `SKILL.md` и скриптов.
- Дампов живых данных и больших JSON-файлов проекта.
- Устаревших хэшей сборки клиента: их берут из `index.html` текущей установки.

## Версионирование

- `v1` — базовый набор: формат, контейнеры, плитки, веб-клиент, проверки.
- `v2` — добавлены кнопки/действия, локальные переменные, привязки, картинки,
  диагностика сборки; правила выдачи объединены с рабочей практикой прямой
  правки по разрешению; проверки распространены на новые сущности.
- При изменении правил или структуры файлов — поднимать версию и описывать
  изменения в commit/tag.
