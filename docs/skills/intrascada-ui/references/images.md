# Картинки, иконки и логотипы

## Где лежат

| Что | Где |
|---|---|
| файлы | `<проект>\images\` — **плоский** каталог, без подпапок |
| индекс | `<проект>\jbase\images.db` (JSON Lines) — дерево групп и записи файлов |
| URL в клиенте | `/images/<имя файла>`, имя кодируется `encodeURI` |

`img.folder` в документе — это **группа для выбора в админке**, а не путь к
файлу. Клиент строит ссылку только из `img.value`, поэтому файл должен лежать
именно в корне `images\`.

## Запись индекса `images.db`

Группа (папка дерева):

```json
{"_id":"img024","parent":"imagegroup","order":3750,"list":"imagegroup",
 "name":"Символы","folder":1}
```

Файл:

```json
{"_id":"TTS-new-logo.ico","title":"TTS-new-logo.ico","name":"TTS-new-logo.ico",
 "order":2000,"parent":"img066"}
```

| Поле | Смысл |
|---|---|
| `_id` | имя файла в `images\` — по нему строится URL |
| `title`, `name` | подпись в админке (обычно совпадает с именем файла) |
| `parent` | группа: `imagegroup` (корень) или `imgNNN` |
| `order` | порядок внутри группы |
| `folder: 1` | признак группы, а не файла |

Файл без записи в `images.db` клиент покажет (URL работает), но в админке его
не будет — выбрать мышью нельзя.

## Ссылка из элемента

Кнопка (проверено на рабочем документе):

```json
"img": {"value":"TTS-new-logo.ico","folder":"img066"},
"imgColor": {"value":"rgba(0,0,0,0)"},
"imgSize": {"value":-5},
"imgPosition": {"value":{"id":"left","title":"Слева"}},
"imgRatio": {"value":32}
```

- `img.value` — имя файла; пустая строка — картинки нет.
- `img.folder` — заполняется для порядка в админке, на рендер не влияет.
- `imgColor: "rgba(0,0,0,0)"` или `"transparent"` — рисовать файл как есть.

## Перекраска SVG (`imgColor`)

Клиент красит **только `.svg`** и только когда `imgColor` не прозрачный:
файл подставляется как CSS-маска, а `imgColor` становится фоном. Поэтому цвет
меняется целиком, включая все заливки внутри SVG; прозрачные области остаются
прозрачными.

```json
"img": {"value":"login_door_clr_opt.svg","folder":"img051"},
"imgColor": {"value":"rgba(82,168,229,1)"}
```

Что из этого следует:

- для цветных логотипов ставьте `rgba(0,0,0,0)`, иначе получится одноцветный
  силуэт;
- `.png`, `.jpg`, `.ico` не перекрашиваются — только масштабируются;
- если SVG нужен в двух цветах, проще два файла, чем маска.

## `.ico` (логотип в шапке)

Клиент рисует картинку через `background-image: url(/images/...)`, поэтому
`.ico` отображается как обычная картинка. Требование к файлу — валидный
Windows-иконка-контейнер: заголовок 6 байт, одна запись 16 байт, дальше кадр.
Практичный вариант — один кадр PNG 256×256 (в готовом файле PNG начинается
со смещения 22). Проверка:

```js
const b = require('fs').readFileSync('images/TTS-new-logo.ico');
console.log(b.length, b.indexOf(Buffer.from([0x89,0x50,0x4e,0x47])));
// 4748 22
```

## Добавить картинку

1. Положить файл в `<проект>\images\`. Имя — латиница, цифры, `-`, `_`, точка;
   без пробелов, `#`, `?` и кириллицы: имя попадает в URL.
2. Дописать запись в `jbase\images.db`: `_id` = имя файла, `parent` = нужная
   группа (`imgNNN`), `order` — по порядку, `name`/`title` = имя файла.
   Группа должна существовать.
3. Проверить отдачу: `GET http://localhost:8088/images/<имя>` → код `200` и
   `Content-Type` `image/svg+xml`, `image/png`, `image/x-icon` и т. п.
4. Перезапуск для самой картинки **не нужен** — файлы читаются с диска по
   запросу. Перезапуск нужен, чтобы новая запись появилась в дереве админки.

Диагностика: на отсутствующий файл сервер отвечает `200` и `text/html`
(SPA-заглушка), а не `404`. Поэтому проверять надо `Content-Type`, иначе
«битая» картинка выглядит как успешный запрос.

## Картинка на весь элемент

У элемента `type: "image"` фон задаётся отдельно от `img*`:

```json
"backgroundImage": {"value":"metal-texture.jpg"},
"backgroundColor": {"type":"fill","value":"rgba(0,0,0,0)"},
"overlayColor": {"value":"rgba(0,0,0,0.35)"},
"contentMode": {"value":{"id":"fill","title":"Заполнить"}}
```

`backgroundImage.value` — имя файла или внешний URL (`https://...`),
`contentMode` — `fill`/`contain` и т. п., `overlayColor` — затемняющий слой.
Фон полотна (`settings.backgroundColor`) — это градиент, а не файл; картинку
на фон ставят отдельным элементом `image` позади остальных.

## Ловушки

- Файл положили в `images\sub\` — URL `/images/sub/name.svg` не сработает.
- Перекрасили цветной логотип через `imgColor` — получили силуэт.
- Обновили файл с тем же именем, а клиент показывает старую версию — это кэш
  браузера: переименуйте файл или обновите с очисткой кэша.
- Удалили файл, а документ на него ссылается — элемент просто останется
  пустым, ошибки в консоли может не быть.
