# Раскладки (`jbase\layout\lXXX.json`)

Раскладка — это экран: полотно фиксированного размера и фреймы, в которые
подставляются контейнеры.

## Схема

```json
{
  "settings": {
    "x": {"value":347}, "y": {"value":443},
    "w": {"value":1920}, "h": {"value":1080},
    "scale": {"value":0.45}, "grid": {"value":1},
    "backgroundColor": {"value":"rgba(255,255,255,1)"},
    "fitW": {"value":true}, "fitH": {"value":true},
    "scrollX": {"value":false}, "scrollY": {"value":false}
  },
  "list": ["frame_1", "frame_2", "frame_3"],
  "elements": {
    "frame_1": {
      "type": "container",
      "widget": true,
      "widgetlinks": {
        "link": {"id":"vc074", "title":"Э_Параметры контейнер", "title2":"Э_Параметры контейнер", "value":{}}
      },
      "x": {"value":110}, "y": {"value":54},
      "w": {"value":1810}, "h": {"value":1025},
      "fitW": {"value":true}, "fitH": {"value":0},
      "alignW": {"value":{"id":"flex-start","lang":"left","title":"Слева"}},
      "alignH": {"value":{"id":"flex-start","lang":"up","title":"Вверх"}},
      "scrollX": {"value":false}, "scrollY": {"value":1},
      "zIndex": {"value":100}, "opacity": {"value":100},
      "visible": {"value":true}, "overflow": {"value":true},
      "data": {},
      "update": 1769094288024
    }
  },
  "selects": {}, "selectContainer": {...}, "selectType": "one",
  "selectOne": "frame_1", "propertyType": "link"
}
```

| Поле фрейма | Смысл |
|---|---|
| `widget: true` | это встроенный контейнер, а не декоративный прямоугольник |
| `widgetlinks.link.id` | id контейнера (`vc074`) |
| `fitW` / `fitH` | растянуть контейнер по ширине/высоте фрейма |
| `alignW` / `alignH` | выравнивание при несовпадении размеров |
| `scrollX` / `scrollY` | прокрутка внутри фрейма (`1` = включена) |
| `update` | служебная метка времени, менять не нужно |

## Пример: `l010` «Параметры»

```text
l010 (1920×1080)
├── frame_3  Меню          x=0    y=2    w=110  h=1078  → vc007
├── frame_2  Строка сост.  x=0    y=0    w=1920 h=52    → vc006
└── frame_1  Параметры     x=110  y=54   w=1810 h=1025  → vc074  (scrollY=1)
```

`l010` — экран «Дополнительные параметры работы оборудования ЭЦ „Мокшан“»,
в котором одна из кнопок открывает `vc096`.

## Как контейнер открывается

Два способа:

1. **Статический фрейм** — у раскладки есть элемент `container` с
   `widgetlinks.link.id = vcXXX`. Контейнер виден сразу при открытии экрана.
2. **Динамический фрейм** — кнопка в другом контейнере создаёт/подменяет фрейм
   по клику:

```json
{
  "action": "singleClickLeft",
  "command": "dialog_any",
  "id": "di0000",
  "value": {
    "targetFrameTable": [
      { "id": "__EqLknonEE",
        "lvar": {"id":"local020","title":"var255","prop":"var255"},
        "lval": "vc096" }
    ]
  }
}
```

Здесь `lval` — id контейнера, а `id` — имя фрейма, который приложение создаёт
во время работы. Такого фрейма может **не быть** в JSON раскладки: это не
ошибка и не повод «добавлять» его в файл.

`vc096` в этом проекте открывается кнопкой `button_5` из `vc010` (экран
`l003`) именно через динамический фрейм `__EqLknonEE` и `local020.var255`.
Поэтому проверять появление контейнера нужно кликом в UI, а не поиском
`vc096` по файлам раскладок.

## Индекс раскладок

`jbase\layouts.db`, JSON Lines:

```json
{"_id":"l010","parent":"lg002","order":5000,"name":"Параметры","status":0,"miss":1}
{"_id":"l003","parent":"lg002","order":875,"name":"Схема энергоцентра","status":0,"miss":1}
```

Имя экрана для пользователя берётся отсюда; в самом `l010.json` названия нет.

## Правка раскладок

- Менять состав фреймов нужно только по явной задаче; чаще достаточно
  отредактировать контейнер.
- При добавлении фрейма: уникальное имя, `type:"container"`, `widget:true`,
  `widgetlinks.link.id`, координаты внутри `settings.w/h`.
- Не забывать про `fitW/fitH`: при `fitW:true` контейнер растянется по ширине
  фрейма, и его внутренние координаты перестанут соответствовать 1:1.
- Раскладки, как и контейнеры, кэшируются в памяти службы: правка видна
  только после перезапуска проекта.

## Третий способ: подмена контейнера по локальной переменной

Статический фрейм можно сделать динамическим, привязав `widgetlinks.link` к
локальной переменной — тогда контейнер меняется без команд `layout`/`dialog`:

```json
"widgetlinks": {"link": {
  "id": "vc001", "title": "Основной контейнер", "title2": "Основной контейнер",
  "enabled": true, "did": "local006", "prop": "main_container",
  "value": {"func": "return inData;"}
}}
```

Как это отрабатывает в клиенте (проверено по коду сборки):

1. При загрузке макета клиент копирует `did`/`prop`/`value.func` из `link` в
   `widgetlinks` и вычисляет `link.id = func(значение локальной переменной)`.
   Пока значения нет, используется `link.id` из документа — стартовый контейнер.
2. Запись локальной переменной (`setval_any` с `local:true`) обновляет значения
   макета и запускает пересчёт привязанных полей; `link.id` пересчитывается
   через `func`.
3. Компонент контейнера видит новый `link.id`, запрашивает `GET_CONTAINER` и
   рисует другой контейнер.

Требования: `enabled: true`, непустой `value.func`, целевой контейнер
существует файлом **и** записью в `visconts.db`. Начальное значение задаётся
`defval` локальной переменной; если его нет — стартовым останется `link.id`.

Отличие от способа с `dialog_any`: там приложение создаёт **новый** фрейм во
время работы (`__EqLknonEE`), а здесь фрейм один и тот же, меняется только
контейнер внутри него.
