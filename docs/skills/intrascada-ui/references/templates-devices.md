# Устройства, папки, плитки и диалоги

> ID, размеры и имена ниже — из проекта-образца. В другом проекте проверяйте
> свои шаблоны, диалоги и переменные по существующим элементам: структура та же,
> идентификаторы почти всегда другие.

## Запись устройства (`jbase\devices.db`)

```json
{"type":"t045","dn":"M1_DI_CabinetTEMP","name":"Температура в шкафу",
 "tags":["di_alm","timeline_di"],"_id":"d0834","parent":"dg174","order":500,
 "props":{"state":{"mu":""},"man_val_set":{"mu":"","save":1}, "...":"..."}}
```

| Поле | Смысл |
|---|---|
| `_id` | идентификатор устройства (`d0834`), используется в `masterLink`/`lval` |
| `dn` | техническое имя (`M1_DI_CabinetTEMP`) |
| `name` | отображаемое имя («Температура в шкафу») |
| `type` | тип: `t045` — дискретный вход (DI), `t040` — аналоговый (AI), и др. |
| `parent` | папка в дереве (`dg174`), а не устройство |
| `order` | порядок внутри папки |
| `tags` | `di_alm`, `timeline_di`, `trends`, `reports`, `settings`, ... |

Тип `t045` (`Discret_Input_Type_v2`) даёт свойства `state`, `value_in/out`,
`man_val_set`, `remont_set`, `signal_blk`, `alm_*`, `warn_*`, `unack`,
`clr_true/clr_false`, `txt_true/txt_false` — их и показывают DI-плитки.

## Папки устройств (`jbase\lists.db`)

Дерево хранится **не в `devices.db`**, а в `lists.db`:

```json
{"_id":"dg172","parent":"dg003","order":2710,"list":"place","name":"Тревоги"}
{"_id":"dg173","parent":"dg172","order":41969,"list":"place","name":"Цилиндры"}
```

Обход поддерева:

```js
const lists = readJsonLines('jbase/lists.db');
const devices = readJsonLines('jbase/devices.db');
const byId = new Map(lists.map(n => [n._id, n]));
const kids = id => lists.filter(n => n.parent === id)
                        .sort((a, b) => (a.order || 0) - (b.order || 0));
const devicesOf = id => devices.filter(d => d.parent === id)
                               .sort((a, b) => (a.order || 0) - (b.order || 0));
```

Все узлы `lists.db` в проекте-образце имеют `list: "place"`; корень дерева —
`place`, верхний уровень — `dg003` («Оборудование»). В другом проекте корень и
имена папок будут свои — смотреть фактические записи с `folder: 1`.

Важно: строки `devices.db` могут дублироваться по `_id`. В снимке от 18.11
встречались два `d0926` с разными именами; после очередного обновления службой
дублей не было. Не полагаться на уникальность: строить список по уникальному
`_id` и предпочитать строку с более полным/актуальным `name`.

## Пример: папка тревог `dg172`

```text
dg172 Тревоги
├── dg174 Общие               8 устройств
├── dg181 Двигатель           6
├── dg173 Цилиндры           23
├── dg178 Генератор          12
├── dg176 Система подачи     32
├── dg175 Система смазки     10
├── dg179 Охлаждение         16
├── dg177 Выхлоп и турбины   11
└── dg180 Вентиляторы        14
```

Итого 132 устройства, все типа `t045`.
Эти цифры — контрольная точка при повторной сборке: если получилось иначе,
проверять дедупликацию и фильтр по `parent`. В снимке от 18.11 (до очередного
обновления службой) было 136 строк из-за дублей `_id`; после обновления
`devices.db` дубли исчезли, но полагаться на это нельзя.

## Заголовок плитки

Формат, принятый в проекте:

```text
<dn> ▪︎ <name>          // U+25AA U+FE0E между частями
M1_DI_EnginRun ▪︎ Состояние двигателя Работа
```

- `masterLink.title` = заголовок, `masterLink.title2` = `dn`.
- На экране имя берётся из **устройства**: в шаблоне `vt105` текст `text_1`
  привязан к `__template_var` (`title: "name"`, `func: "return inData;"`),
  и движок подставляет имя устройства. Поэтому смена `name` в `devices.db`
  меняет подпись плитки без правки контейнера.
- Длинные имена обрезаются по ширине плитки (`overflow`), переноса нет.

## Шаблон DI-плитки `vt105`

Файл `jbase\template\vt105.json`, полотно **310×30**:

| Элемент | Что это | Геометрия |
|---|---|---|
| `text_1` | имя устройства, шрифт 16, справа | `0,0 268×30` |
| `circle_1` | основной индикатор состояния | `275,10 20×20` |
| `circle_2` | мигание неквитированной тревоги | `275,10 20×20` |
| `image_1` | иконка «в ремонте» | `292,0 18×20` |
| `image_2` | иконка «сигнализация заблокирована» | `286,0 21×21` |
| `text_2` | буква «П» (ручная подстановка) | `266,1 18×18` |
| `action_1` | кликабельная область | `50,0 450×30`, `zIndex 10000` |

Состояния индикатора задаются функциями на `state1…state10`
(`clr_true`, `clr_false`, `unack`, `no_link`, `remont_set`), цвета —
`green / yellow / red / black / grey`.

При вписывании в плитку другой ширины шрифт масштабируется примерно как
`16 × w / 310`. Для `w = 280` это ≈ 14.5 px; при 14 px длинные имена
начинают обрезаться раньше. Кружок и иконки остаются того же размера,
поэтому при сильном уменьшении ширины они могут наезжать на текст.

## Шаблон AI-плитки `vt104`

Полотно **500×30**, аналоговое значение и единицы измерения. В контейнере
`vc096` такие плитки занимали широкую левую полосу (`500×30`), менять их
геометрию при добавлении DI-плиток не нужно.

## Привязка клика к диалогу

| Тип устройства | Диалог | Локальная переменная |
|---|---|---|
| DI (`t045`) | `di0039` «DI. Настройки датчика» | `local063.DI_id` |
| AI (`t040`) | `di0028` | `local002.ai_id` |

Проверять по уже существующей плитке того же типа в проекте: id диалога и
`lvar` могут отличаться в другой конфигурации.

Структура действия:

```json
"actions": {
  "type": "multi",
  "action_1": {
    "left": [
      {
        "action": "singleClickLeft",
        "id": "di0039",
        "title": "DI. Настройки датчика",
        "command": "dialog_any",
        "value": {
          "active": true,
          "targetFrameTable": [
            { "id": "__fkXjsoPK_",
              "lvar": {"id":"local063","title":"DI_id","prop":"DI_id"},
              "lval": "d0834",
              "freeze": false }
          ]
        }
      },
      { "action": "longClickLeft", "value": {} }
    ],
    "right": []
  }
}
```

Проверка: `lval` должен быть равен `masterLink.id`. В старых файлах
встречаются расхождения (плитка одного устройства открывает диалог другого) —
это дефект, но исправлять его без разрешения владельца нельзя.

## Диалог (`jbase\dialog\diXXXX.json`)

Устроен как контейнер, но с параметрами окна:

```json
"settings": {
  "w": {"value":300}, "h": {"value":800},
  "position": {"value": {"id":"right","title":"Справа"}},
  "outsideClose": {"value":1},
  "dialogScale": {"value":0},
  "fitW": {"value":false}, "fitH": {"value":true}
}
```

Элементы — `image`, `rectangle`, `text`, `button`, `checkbox`, `group`.
Диалог получает выбранное устройство через `local063.DI_id` (или
`local002.ai_id`) и показывает его свойства.
